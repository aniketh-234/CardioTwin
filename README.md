## Project overview and healthcare use case

Static EHR-style records capture background cardiovascular risk factors but do not show recent day-to-day changes. **CardioTwin** combines a synthetic historical health profile with a rolling 28-day sequence of daily sensor-style measurements. The backend updates a virtual patient's stored state after each new day, runs saved trained models, evaluates transparent adverse-trend rules and displays data readiness and reference-replacement sensitivity explanations.

The conceptual use case is **longitudinal cardiovascular risk review**, not clinical triage, treatment guidance or deployment as a medical device. The prediction target is a **hypothetical first cardiovascular event within five years**, generated by a custom simulator.

## Dataset

The custom synthetic benchmark includes **4,000 patients**, each with **28 daily records** (112,000 daily rows), and **888 simulated events**. The patient-level split is **2,400 training / 800 validation / 800 testing**, with **177 simulated events** in the test set.

- **Historical features (8):** age, sex, BMI, systolic blood pressure, total cholesterol, HDL cholesterol, smoking status and diabetes status.
- **Daily measurements:** resting heart rate, heart-rate variability, steps, sleep duration, home-cuff systolic blood pressure and measurement coverage.
- **Target:** a simulated cardiovascular event within five years; not an observed clinical endpoint.

The historical and daily streams are linked by the same synthetic patient identity. The separately examined Synthea sample was **not used to train the delivered models**, because it did not provide enough usable future events for the neural-model evaluation.

## Technical stack and ML models

| Component | Technology |
|---|---|
| Backend/API | Python standard-library HTTP server |
| Neural models | PyTorch — MLP, 1D CNN, LSTM, GRU |
| Baselines and evaluation | scikit-learn — logistic static/fusion baselines |
| Data preparation | NumPy, pandas |
| Frontend | HTML, CSS, JavaScript |
| Persistence | SQLite patient state and event journal |

The original validation-selected model was **logistic fusion** (lowest validation Brier score). The interactive dashboard uses **Hybrid CNN + rules** to demonstrate both trained inference and interpretable trend-review logic; this is **not** a claim of superior predictive performance.

## System architecture

1. **Input:** historical EHR-style profile and rolling 28-day sensor-style sequence.
2. **Validation and preprocessing:** schema/range checks, training-fitted transformations and missingness information.
3. **Data readiness:** coverage and completeness checks; withhold output when insufficient.
4. **Model inference:** static branch plus temporal 1D CNN, fused to estimate the synthetic five-year outcome.
5. **Trend review:** compare the latest 7 days against the previous 21 days; at least two qualifying adverse trends produce a review flag.
6. **Explainability:** historical-feature and sensor/week reference-replacement sensitivities, plus non-mutating scenario comparisons.
7. **Persistence and UI:** SQLite journal and patient state, browser trajectory charts, prediction and review reasons.

**The trend rules do not change the CNN probability.** Their thresholds are engineering heuristics, not medical danger thresholds. Sensitivity outputs are not SHAP values or causal treatment effects.

## Held-out synthetic evaluation

| Review policy | Detected events | False alerts | Missed events |
|---|---:|---:|---:|
| CNN at 50% threshold | 80 | 39 | 97 |
| CNN at 50% OR trend-review rules | 89 | 78 | 88 |
| CNN at validation-matched 37.93% threshold | 101 | 80 | 76 |

The CNN achieved approximately **83% test accuracy** and **0.84 ROC-AUC** on the synthetic benchmark. The hybrid policy detected nine additional events relative to CNN at 50%, but generated 39 additional false alerts. The exploratory lower-threshold comparison **does not establish incremental predictive value from the rules**. See [hybrid evaluation results](https://github.com/aniketh-234/CardioTwin/blob/main/CardioTwin_Tech_Builders_GitHub_Ready/Tech%20Builders_Manipal%20Institute%20of%20Technology%20Manipal/artifacts/hybrid_evaluation.json).

## How to run

Open a terminal **inside the nested project directory** shown in the deliverables section. Python and dependencies must be installed. On Windows:

```powershell
python -m pip install -r requirements.txt
python -m backend.server
```

Then open **http://127.0.0.1:8000/** in a browser. Stop the server using **Ctrl+C**.

To run the software tests:

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
```

To reproduce the recorded hybrid-policy comparison:

```powershell
python -m ml.evaluate_hybrid
python -m ml.compare_review_policies
```

The supplied checkpoints support inference without retraining. Use synthetic demonstration patients only. The local server is not a production-authenticated clinical service.

## Limitations and future work

The models were trained and evaluated only on a custom synthetic simulator. There is no commercial wearable integration, independent real-patient validation, clinically approved alert threshold or causal intervention model. Future work requires governed matched longitudinal data, meaningful clinical endpoints, external validation, calibration, subgroup assessment, clinician review of alert burden and secure device/EHR integrations.
